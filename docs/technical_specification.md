# Техническое задание РГР

## 1. Название проекта

Система обнаружения подозрительной активности в сети связи.

## 2. Предметная область

Система применяется в инфраструктуре оператора связи. Обрабатываются события от RADIUS/AAA-серверов, BRAS, SBC, DNS, NMS, firewall, gateway, router, BSC и LTE base station.

## 3. Цель разработки

Разработать веб-приложение для учета, анализа и корреляции сетевых событий с разграничением доступа по ролям, журналированием действий и автоматическим формированием инцидентов безопасности.

## 4. Пользователи и роли

| Роль | Назначение |
|---|---|
| `admin` | Управляет пользователями, ролями, узлами, правилами, доступами и журналом. |
| `security_engineer` | Анализирует события, запускает корреляцию, работает с оповещениями и инцидентами. |
| `operator` | Создает сетевые события, просматривает разрешенные события/инциденты и сводную панель. |

## 5. Функциональные требования

| Код | Требование | Реализация |
|---|---|---|
| F1 | Регистрация и вход пользователя | `/api/auth/register`, `/api/auth/login` |
| F2 | Авторизация по ролям | JWT + `require_role` |
| F3 | CRUD сетевых узлов | `/api/nodes`, управление только `admin` |
| F4 | CRUD сетевых событий | `/api/events`, создание для авторизованных пользователей |
| F5 | CRUD правил обнаружения | `/api/rules`, управление только `admin` |
| F6 | CRUD инцидентов | `/api/incidents`, удаление только `admin` |
| F7 | Расчет риска события | `risk_score`, `risk_level`, `detection_reason` |
| F8 | Корреляционный анализ | `/api/analysis/run`, `/api/analysis/alerts` |
| F9 | Импорт и экспорт CSV | `/api/dataset/import`, `/api/dataset/export/*` |
| F10 | Аналитика и dashboard | `/api/analytics/*` |
| F11 | Журнал действий | `/api/logs` |
| F12 | Управление пользователями | `/api/auth/users/{id}` |

## 6. Требования к безопасности

| Требование | Реализация |
|---|---|
| Хеширование паролей | `passlib[bcrypt]` |
| Проверка сложности пароля | Pydantic policy: длина, буква, цифра, запрет пробелов |
| JWT после входа | `python-jose`, `Authorization: Bearer` |
| Ограничение API по ролям | `get_current_user`, `require_role` |
| Запрет доступа к чужим данным | `access_control.py` для событий и инцидентов |
| Журналирование действий | `audit_logs` |
| Журнал неуспешных входов | `login_attempt_logs` |
| Блокировка перебора пароля | lockout после 5 неудачных попыток |
| Валидация входных данных | IP, enum, числовые границы, XSS-маркеры |
| Единый формат ошибок | `code`, `message`, `details`, `detail` |

## 7. Структура интерфейса

Основные разделы: вход, регистрация, dashboard, события, карточка события, узлы, правила, инциденты, карточка инцидента, анализ, correlation alerts, аналитика, dataset, журнал, пользователи.

Подробный макет описан в `docs/interface_mockup.md`.

## 8. Структура базы данных

Основные таблицы:

- `users`
- `network_nodes`
- `network_events`
- `detection_rules`
- `correlation_alerts`
- `correlation_alert_events`
- `incidents`
- `audit_logs`
- `login_attempt_logs`
