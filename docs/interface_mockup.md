# Макет интерфейса

Документ описывает логическую структуру экранов. Реальный интерфейс реализован во frontend на React/Vite.

## Общая навигация

Верхнее меню после входа:

| Раздел | Admin | Security engineer | Operator |
|---|---:|---:|---:|
| Панель | да | да | да |
| События | да | да | да |
| Узлы | да | да | да |
| Правила | да | да | да |
| Инциденты | да | да | да |
| Аналитика | да | да | да |
| Анализ | да | да | нет |
| Набор данных | да | да | нет |
| Журнал | да | да | нет |
| Пользователи | да | нет | нет |

## Экран входа

Элементы:

- поле имени пользователя;
- поле пароля;
- кнопка входа;
- ссылка на регистрацию;
- сообщение об ошибке без технических деталей;
- таймер блокировки после серии неудачных входов.

## Экран регистрации

Элементы:

- имя пользователя;
- email;
- пароль;
- кнопка регистрации.

Безопасность: пароль проверяется по сложности, новый пользователь получает роль `operator`.

## Панель мониторинга

Элементы:

- карточки количества событий, подозрительных событий, критических событий, активных инцидентов;
- средний риск;
- критические оповещения;
- узлы warning/offline;
- распределение риска;
- топ IP-источников;
- топ типов событий.

Для `operator` аналитика строится по разрешенным событиям и инцидентам.

## События

Элементы:

- таблица событий;
- фильтры по типу, критичности, риску, IP и узлу;
- кнопка создания события;
- действия редактирования для `admin` и `security_engineer`;
- удаление только для `admin`.

Карточка события показывает риск, причину обнаружения, связанные alerts и incidents.

## Форма события

Поля:

- узел;
- правило обнаружения;
- IP источника;
- IP назначения;
- протокол;
- тип события;
- сообщение;
- критичность.

Валидация: IP-адреса, enum-значения, XSS-маркеры.

## Узлы

Элементы:

- таблица узлов;
- фильтры по типу и статусу;
- создание/редактирование/удаление только для `admin`.

## Правила

Элементы:

- таблица правил;
- фильтры по типу события и активности;
- создание/редактирование/удаление только для `admin`.

## Инциденты

Элементы:

- таблица инцидентов;
- фильтры по статусу и критичности;
- создание инцидента из события;
- редактирование для `admin` и `security_engineer`;
- удаление только для `admin`.

Карточка инцидента содержит связанную информацию и управление доступом.

## Анализ и correlation alerts

Доступ: `admin`, `security_engineer`.

Элементы:

- кнопка запуска анализа;
- таблица correlation alerts;
- карточка alert;
- изменение статуса alert;
- создание incident из alert;
- удаление alert только для `admin`.

## Dataset

Доступ: `admin`, `security_engineer`.

Элементы:

- импорт CSV;
- экспорт событий;
- экспорт инцидентов;
- скачивание примера CSV.

## Журнал

Доступ: `admin`, `security_engineer`.

Элементы:

- журнал действий пользователей;
- журнал неудачных входов;
- время, пользователь, действие, сущность.

## Пользователи

Доступ: `admin`.

Элементы:

- таблица пользователей;
- текущая роль;
- статус активности;
- смена роли;
- отключение/включение учетной записи.

Ограничение: администратор не может отключить сам себя или снять собственную роль администратора.
